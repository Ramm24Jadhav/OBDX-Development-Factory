When the model server fails

  • ErrorThe job stops and shows the provider's error on its page. There is no fallback provider to switch to.
  • Rate limitThe factory waits and tries again within a time budget.
  • Daily limitIt stops with "quota exhausted". Code generation keeps the files written; Continue generation goes on later.
  • Too largeThe prompt is built again with less context until it fits the learned limits.

Limits learned from the provider

When a server refuses a request for its size or rate, the factory keeps the limit for 7 days so it does not ask too much again.

Data classification

Where each kind of the bank's content may go, and where it goes with the models in use. A server is inside the bank when it is this computer, a private address, or listed in factory.knowledge.internal-hosts.

ContentRuleNowState

Keep restricted content local: leave FACTORY_KNOWLEDGE_EXTERNAL_MODELS off (the default). The factory does not block an outside server for code; to keep code inside the bank, choose a model server on this computer or the bank's network.

Rotating an API key

  1. On Overview, open the provider's Settings, enter the new key and press Test connection: the test uses the new key; the stored one stays in use.
  2. When the test succeeds, press Save: the new key replaces the old one, encrypted on the server.
  3. Revoke the old key at the provider. Every change is in the audit log (Administration).

Policies

  • API keys are stored on the factory server, encrypted, and never sent back to the browser.
  • The bank's code goes only to the model server chosen here. Choose a server on this computer or the bank's network for sensitive code.
  • Generated code is checked against the version pack rules and never written to trunk: it is delivered as a patch or an SVN branch.
  • Every model setting change is recorded in the audit log (Administration).
