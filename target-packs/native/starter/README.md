# OBDX mobile apps (Swift and Kotlin)

The starter of the native target pack: two apps that call the bank's OBDX REST services, built from the same approved
screens.

| Folder | App | Build and test |
|---|---|---|
| `android/` | Kotlin, Jetpack Compose, Material 3 (min SDK 26) | `cd android && ./gradlew test` (Robolectric with the Compose test rule), `./gradlew assembleDebug`; open in Android Studio |
| `ios/` + `Package.swift` | Swift 6, SwiftUI (iOS 17) as a Swift package | `xcodebuild test -scheme ObdxApp -destination 'platform=iOS Simulator,name=iPhone 16'` from this folder (XCTest with ViewInspector); the app target is generated by XcodeGen from `ios/App/project.yml` |
| `shared/i18n/en.json` | The texts of both apps | Gradle puts it on the Android classpath; the Swift package bundles it |
| `scripts/run-on-device.sh` | Smoke test on a phone, emulator or simulator | `bash scripts/run-on-device.sh android` or `bash scripts/run-on-device.sh ios "iPhone 16"` |

Each screen is written twice with the same fields, actions, texts and rules: `<Screen>Screen.kt` and `<Screen>View.swift`.
The components have the same names and props on both platforms (`BxTextField`, `BxAmountField`, `BxSelectField` ...
with testTag or testID, label, value, error, options, required, readOnly, maxLength, helpText, placeholder), so a
screen reads alike in both.

- **Services**: `api/ApiClient.kt` and `Api/ApiClient.swift` call OBDX over https only, keep the session cookie in
  memory (never written to the device) and send a fresh nonce with every call that changes something. Set the bank's
  address in `android/gradle.properties` (`obdx.baseUrl`) and `ios/App/project.yml` (`OBDX_BASE_URL`).
- **Forms**: `FormModel` on both platforms: values, rules (required, maxLength, check) and messages.
- **Theme and motion**: `Theme.kt` / `Theme.swift` carry the bank tokens (from `target-packs/components/tokens`), light
  and dark; `Motion.kt` / `Motion.swift` the motion spec (`target-packs/components/motion.json`): sections rise in, a
  field shakes once when its error appears, a chosen option springs. Nothing moves when the device turns animations
  off or asks for reduced motion.
- **Privacy**: the Android window is secure (no screenshots or recent-apps preview of balances); the iOS app blurs
  when it leaves the foreground. Nothing secret is kept on the device.

## Certificate pinning

Both apps talk only to a server whose certificate chain holds one of the bank's public keys (`CertificatePins` in
`api/` and `Api/`; the check runs during the TLS handshake, before anything is sent). When the check fails the app
says: "The app could not confirm it is talking to your bank. Update the app from the store; if it is up to date, try
another network."

The pins are settings the bank sets, the same in both apps:

| | Pins | Day they stop being enforced |
|---|---|---|
| Android, `android/gradle.properties` | `obdx.pins=sha256/AAA...=,sha256/BBB...=` | `obdx.pinsExpire=2027-06-30` |
| iOS, `ios/App/project.yml` | `OBDX_PINS: sha256/AAA...=,sha256/BBB...=` | `OBDX_PINS_EXPIRE: 2027-06-30` |

A pin is the SHA-256 of the server key's SubjectPublicKeyInfo, in base64. Get it from the server or a certificate file:

```bash
openssl s_client -connect obdx.bank.example:443 -servername obdx.bank.example </dev/null 2>/dev/null \
  | openssl x509 -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | base64
openssl x509 -in next.pem -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | base64
```

- **Always ship two pins**: the key in use and the key of the next certificate (a backup key the bank already holds).
  Before the certificate changes, release an app update that has the new key's pin, and wait until most customers
  have it; an app without the new pin cannot reach the bank after the change and shows the message above.
- **The expiry** is the safety net for apps nobody updated: after that day the pins are not checked (the platform's
  normal certificate checks still are). Set it a few months past the next planned certificate change.
- Keys: RSA 2048 and 4096, EC P-256 and P-384. Empty pins turn pinning off: only for development against a test server.
- Tests: `CertificatePinsTest.kt` and `CertificatePinsTests.swift` check the same certificate gives the openssl pin.

## The iOS project (XcodeGen)

The Xcode project is not checked in: [XcodeGen](https://github.com/yonaskolb/XcodeGen) writes it from
`ios/App/project.yml`, so project changes are reviewable text and never merge conflicts.

1. Install XcodeGen once: `brew install xcodegen`.
2. `cd ios/App && xcodegen generate` writes `ObdxMobile.xcodeproj` and `Info.plist` (do not commit them; run it again
   after changing `project.yml` or pulling).
3. Open `ios/App/ObdxMobile.xcodeproj`, choose the `ObdxMobile` scheme and a simulator, and run. The app's code is the
   Swift package at this folder's root (`Package.swift`); the project depends on it.
4. Set the bank team and signing in `project.yml` (`DEVELOPMENT_TEAM`, `CODE_SIGN_STYLE`) for builds on phones.

The unit tests are the Swift package's: `xcodebuild test -scheme ObdxApp -destination 'platform=iOS Simulator,name=iPhone 16'`
from this folder, or open `Package.swift` in Xcode. Views are tested with
[ViewInspector](https://github.com/nalexn/ViewInspector) (`ios/Tests/ObdxAppTests/Home/HomeViewTests.swift`; each
generated screen gets a `<Screen>ViewTests.swift` that finds every field and action by its id).

## Smoke test on a device

`scripts/run-on-device.sh` builds the app, installs it, starts it, waits a few seconds (`WAIT=15` for longer) and
checks it is still running. It exits 0 when the app started, 1 when it did not (with the crash for Android).

- **Android**: a phone with USB debugging on, or a running emulator; `adb` on the PATH.
  `bash scripts/run-on-device.sh android` (or `android <serial>` when `adb devices` lists more than one).
- **iOS**: on a Mac with Xcode and XcodeGen; boots the simulator if needed.
  `bash scripts/run-on-device.sh ios "iPhone 16"` (a name from `xcrun simctl list devices`).
  A phone needs signing and is not covered: run from Xcode.
