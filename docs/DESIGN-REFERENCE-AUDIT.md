# Design reference audit

This audit takes published design and interaction guidance from Linear, Vercel (Geist and the web interface
guidelines), shadcn/ui (and the Radix primitives it documents) and Figma, and maps it to the OBDX Development
Factory UI. Every row can be built in the current Oracle JET / Knockout app with plain CSS and the factory's own
components. Nothing here copies another vendor's branding, fonts, icons or colours.

Pages were fetched on 2026-10-29. Fetch notes:

- `linear.app/docs/keyboard-shortcuts` and `linear.app/docs/configuring-workflows` returned 404. Shortcut facts come
  from the Search and Select issues pages; status categories come from the Issue status page as indexed by search.
- `linear.app/method` lists section titles only; it adds little UI guidance and is not cited below.
- shadcn/ui now shows Base UI versions by default. Its pages do not describe keyboard or ARIA behaviour, so the
  Radix primitive pages were fetched for those patterns. The `sonner` URL now shows the shadcn Toast page.
- `vercel.com/design/guidelines` exists and was fetched in full.
- Figma help pages do not give a naming convention; naming guidance comes from Figma's resource library and blog.

The current UI already has `--fx-*` tokens, but older `--factory-*` and `--dz-*` names are still in `app.css`. Several
rows below start from that.

## Priorities

1. Command palette on Ctrl K with Go to, page actions, Recent and prefixes (rows 1–2). Keep code search as a prefix.
2. Shared status categories and one badge style across Requirements, Changes, Agent Runs and External Review (row 5).
3. Workspace switcher with workspace-as-filter navigation, and state in the URL (rows 10–11).
4. Resizable three-pane Changes workbench, with the assistant in a sheet on small screens (rows 12–13).
5. Side sheet for detail views (Agent Run logs, notifications, requirement history) (row 13).
6. Table keyboard navigation, multi-select and bulk action bar (row 4).
7. Token clean-up: retire legacy names, add ramps with fixed step roles, add High contrast mode, lint in the build (rows 8, 9, 21).
8. Progress toasts with Undo for reversible actions; forms that validate without blocking (rows 18–19).
9. Empty, loading and error states on every page (row 20).
10. Saved list views and a Compact density option (rows 6–7), then shortcut help sheet and toggle groups (rows 3, 15).

## Not adopted, and why

- **Web fonts or icon sets loaded from the internet.** Many bank sites block outbound traffic and the factory runs
  on premise. Keep the system font stack and bundled icons; ship any font inside the build.
- **Vendor typefaces, logos, colour palettes or names.** Their principles are used; their branding is not.
- **Heavy or decorative animation** (springs, page transitions, shimmer loops). Keep short CSS transitions on
  `opacity` and `transform` only, never `transition: all`, and turn motion off under `prefers-reduced-motion`.
- **Adopting React libraries** (cmdk, TanStack Table, Base UI, Radix, Sonner). The app is Knockout/JET; the patterns
  and ARIA behaviour are rebuilt as `fx-*` components instead.
- **Optimistic updates for server-side changes that touch bank code** (commits, SVN, Jenkins, approvals). These wait
  for the server and show progress; optimism is only for local, reversible UI actions.
- **Mobile floating bottom bar for navigation.** The tool is used on desktops; a sidebar drawer is enough at small
  widths.
- **Fully manual, workspace-wide ordering of items.** Shared manual order changes what everyone sees; with audit needs
  in a bank, ordering stays per user or by a field.
- **Desktop-app chrome** (in-app tabs, back/forward buttons). The browser already provides these.
- **APCA-only contrast checks.** Bank accessibility policies usually cite WCAG 2.x; check WCAG 2.2 AA first and use
  APCA only as an extra signal.
