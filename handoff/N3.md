# Handoff: N3 · the motion layer and the five effect categories in React Native

Commit: see `git log` on branch `claude/catalogue-phone-304429` ("Motion layer and the five effect categories in React Native")

## Built

**M1, the motion layer**, in `react-native/src/motion.tsx` on React Native's `Animated` only (no new dependency):
`Enter` / `useEnter` (the component style's scroll effect), `Press` (its click effect: press, bounce, Android ripple),
`Shake` / `useShake`, `Pop` / `usePop`, `Roll` / `useRoll`, `useGrow`, `useSlide`, `useOpen` (sheet, dialog, drop),
`useShimmer`, `useCycle`, `useStagger`, `useProgress`, `useReducedMotion`, `DURATION`, `EASING` (from the bank tokens).
`useReducedMotion` follows `AccessibilityInfo.isReduceMotionEnabled` and its change event; every effect then shows its
end state. The theme now carries `motion: { click, scroll }` from the component style (none when the style sets none,
as on the web).

Where it is applied (so every component gets it):

| Spec in motion.json | React Native |
|---|---|
| enter "style" | `FieldShell` (every field), `Card`, `Choices`, every panel in the shared parts and G1–G6 (`Enter`) |
| press "style" | `Button`, `IconButton`, `Card` (with `onAction`), `Choices`, `Dropdown`, the shared `Touch` (every pressable in G1–G6), chips, tabs, table rows |
| error "shake" | `FieldShell`, `Choices`, `Segment`, `Chips`, `CodeBoxes`, `SliderControl`, `FileUpload` |
| change "roll" | `NumberInput`, tile values, `AccountBalance`, calculator results |
| change "pop" | choice marks, chips, `MultiSelect` chips, code slots, the current step |
| change "slide" | `Tabs` (a measured marker), `Segment` (and everything built on it) |
| change "settle" | `DataTable` rows, list rows, timeline events, `FileUpload` files |
| change "grow" | progress bars, bar charts |
| open "spring" / "drop" | `Dialog`, `Dropdown`, the forms' sheets, the shared `Sheet`; `Autocomplete` suggestions drop |
| loading "shimmer" | `Button` with `busy`, `Skeleton` |
| switch "spring" | the platform `Switch` springs by itself |
| toast "slide-down" | `Toast` messages |

Phone versions of hover ideas: GlareHover sweeps on press, MagneticButton leans towards the finger while held,
SpotlightCard's light follows the finger, TiltCard tilts with it. Gradients use React Native's
`experimental_backgroundImage` (0.76 and later); GradientText colours each character along the gradient (React Native
cannot fill text); GlassPanel is translucency only (React Native cannot blur what is behind a view; expo-blur's
`BlurView` can go behind it). Every gesture has a screen reader action (SlideToConfirm, HoldToConfirm, SwipeRow,
ScrubField, OptionWheel, CardStack, Carousel).

## Checks run

- `npm run check` in `target-packs/components/react-native` (Node 22): typecheck clean; Jest 11 suites, 121/121 passed
  (`test/motion.test.tsx`: enter, shake, grow, bounce, slide, and the end state under reduced motion;
  `test/effects.test.tsx`: all 69 through `accessibilityProblems()`, gestures through their screen reader actions,
  text effects, reduced motion).
- Jest's renderer has no native animation thread, so `motion.test.tsx` runs the native-driver animations in JS (it
  wraps `Animated.timing` and `Animated.spring`); `test/setup.ts` drops React's "not wrapped in act" warning for
  animations that end after a test. On a device the native driver runs them.
