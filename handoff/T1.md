| Vue 3 (web) | `target-packs/vue` | `vue` (single-file components, `<script setup lang="ts">`) | Vite, Vue 3.5, vue-router, Vitest and Vue Test Utils: `src/components` (14 SFCs on a shared `Field.vue`, the same props as the other packs, with `v-model`), `src/forms/useForm.ts` (+ a spec), `src/api/client.ts` (session cookie and nonce, as the JET Core Pack's), `src/i18n`, `src/router`, a home page | 12 | screen.vue, screen.spec.ts, api.ts |

Motion: the Vue starter's `components.css` carries the motion spec with the `--bx-dur-*` and `--bx-ease-*` tokens
(sections rise in, a field shakes once on its error, a chosen option pops, a pressed button gives, a busy button
shimmers) and stops everything under `prefers-reduced-motion`. Capacitor has the React starter's components, so it
gets whatever motion the main session adds to the React starter (M3).

### Java (written here, not compiled: run the tests)

- `target/TargetPack.java`: `VUE = "vue"`, `isVue()`; the syntax doc lists vue.
- `target/TargetPacks.java`: `BUILT_IN` adds `vue` and `capacitor`; the syntax check accepts `vue`.
- `target/ScreenScaffolder.java`: `screen()` sends Vue packs to the new `vueScreen` and `vueElement` (an SFC with
  `v-model="form.values.x"`, `:error="form.errors.x"`, `testID`, the same texts, rules, options and actions as the JSX
  packs; actions are `<Button ... @press>`). Capacitor uses the JSX path unchanged. `test()` needed no change.
- `modernization/TechnologySettings.java`: `TECHNOLOGIES`, `NAMES` and `DEFAULTS` add Vue 3 and Capacitor; both
  "Choose ..." errors now list the technologies from `NAMES` (one constant, `CHOOSE`).
- `modernization/TechnologyCatalogue.java`: the starter stack reads `vue` and `@capacitor/core`; a Capacitor starter
  builds with "Vite and Capacitor (Gradle and Xcode)".
- Tests: `TargetPacksTest` (the pack list, Vue and Capacitor assertions, and a new test that the Capacitor starter's
  components, forms, texts and templates equal the React pack's), `ScreenScaffolderTest` (`scaffoldsAVuePage`,
  `scaffoldsACapacitorPageAsTheReactOne`).

## For the shared files (the main session applies these)

- **target-packs/catalogue.json**: give `vue` and `capacitor` their `packVersions`, for example
  `[["1.0.0","2026-11-06","First release: single-file screens with Vitest tests"]]` and
  `[["1.0.0","2026-11-06","First release: the React screens in a Capacitor shell for Android and iOS"]]`.
- **target-packs/README.md**: two rows in the packs table:
  - `vue` · A new web app in Vue 3 (Vite, TypeScript, single-file components, `syntax: vue`) on the OBDX REST services · The React preview (the same layout and classes)
  - `capacitor` · An Android and iOS app made of the React web screens in a Capacitor shell · The React preview (they are the React screens)
- **CI** (`.github/workflows/build.yml`), a job per pack:

  ```yaml
  vue-starter:
    runs-on: ubuntu-latest
    defaults: {run: {working-directory: target-packs/vue/starter}}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: {node-version: 22}
      - run: npm install
      - run: npm run typecheck
      - run: npm test
  capacitor-starter:
    runs-on: ubuntu-latest
    defaults: {run: {working-directory: target-packs/capacitor/starter}}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: {node-version: 22}
      - run: npm install
      - run: npm run typecheck
      - run: npm test
      - run: npx vite build && npx cap sync --inline || true   # android/ and ios/ are created by `cap add`, not kept in the starter
  ```

  The starters have no lock files yet (this session cannot run `npm install`); commit the lock files from the first
  CI run, or run `npm install` once and commit them.
- **docs**: `docs/DEVELOPMENT.md` and `docs/MODERNIZATION.md` can name the two packs; `Workspace.java`'s comment on the
  target pack id lists the old six (T2 updates it).
