# Handoff: T2 · target pack native Swift and Kotlin

Commit: see `git log` on branch `claude/catalogue-phone-304429` ("Target pack Swift and Kotlin")

## Built

`target-packs/native` (`syntax: native`): each approved screen is written for both apps, with the same fields,
actions, texts, rules and identifiers.

| Part | Android | iOS |
|---|---|---|
| Screen | Jetpack Compose `android/.../screens/{module}/{Screen}Screen.kt` (template `Screen.kt`) | SwiftUI `ios/Sources/ObdxApp/Screens/{module}/{Screen}View.swift` (template `View.swift`) |
| Test | Robolectric + Compose test rule (`ScreenTest.kt`: every id present, the required messages) | XCTest + ViewInspector (`ViewTests.swift`: every id present) |
| API file | `api/{module}Api.kt` (template `Api.kt`, org.json) | `Api/{module}Api.swift` (template `Api.swift`, Codable) |
| Navigation | `AppNavigation.kt` (navigation-compose) | `AppNavigation.swift` (NavigationStack) |
| Starter | Gradle (AGP 8.13, Kotlin 2.2, Compose BOM 2025.10, min SDK 26): `ApiClient` (https only, cookie in memory, nonce), `FormModel`, `Texts`, `Theme` (bank tokens, light and dark), `Motion` (enter, shake; off when the system animator scale is 0), `Fields` and `Layout` (13 components, 48 dp targets, live-region errors), a home screen, `FLAG_SECURE`, no backup, no cleartext, a `FormModelTest` | Swift package at the app root (Swift 6, iOS 17): `ApiClient` (ephemeral session, https only, nonce), `FormModel`, `Texts`, `Theme`, `Motion` (reduced motion respected), `Fields` and `Layout` (the same 13 components, accessibility identifiers, announced errors), a home view, the app entry in `ios/App` (blurs in the app switcher), `FormModelTests` |
| Texts | `shared/i18n/en.json`, one file: on the Android classpath (Gradle) and bundled by the Swift package | |

Rules (7): no web views for screens, services only through the API client, no secrets on the device, https only, texts
from i18n, colours from the theme, no logging. Recipes: the screen (both platforms), the API files, texts and
navigation.

### Java (written here, not compiled: run the tests)

- `target/TargetPack.java`: `NATIVE = "native"`, `isNative()`.
- `target/TargetPacks.java`: `BUILT_IN` adds `native`; a native pack must have `structure.screenIos`, `testIos`,
  `apiIos`, `navigationIos` and `templates.screenIos`, `testIos`.
- `target/ScreenScaffolder.java`: `forFile` also matches `screenIos` and `testIos` for native packs; `screen()` sends
  native packs to `kotlinScreen`; new `swiftScreen`, `nativeScreen`, `nativeElement` (Kotlin named arguments with
  trailing commas; Swift arguments in the components' declared order without a trailing comma; an empty Swift
  dictionary is written `[:]`), `nativeInitial`, `kotlinQuote` (escapes `$`), `swiftQuote`; `test()` gained an
  overload with the template name and quotes the ids for Kotlin or Swift; `common()` adds `modulePackage` (the
  module as a Kotlin package name).
- `modernization/TechnologySettings.java`: native in `TECHNOLOGIES`, `NAMES` ("Swift and Kotlin"), `DEFAULTS`; its
  language row says "Kotlin and Swift 6, strict concurrency".
- `modernization/TechnologyCatalogue.java`: `nativeStack` reads the Kotlin version (Android build) and the Swift tools
  version (Package.swift); `build()` says "Gradle and Xcode" for it.
- `workspace/Workspace.java`: the comment on the target pack id lists every pack.
- Tests: `TargetPacksTest` (the pack list and native assertions, including the iOS recipe part),
  `ScreenScaffolderTest.scaffoldsANativeScreenForAndroidAndIos` (both screens, both tests, the quoting),
  `TechnologyStackTest` (Vue, Capacitor and native stacks).

## For the shared files (the main session applies these)

- **target-packs/catalogue.json**: `native` gets `packVersions`, for example
  `[["1.0.0","2026-11-06","First release: Compose and SwiftUI screens from one Screen Model, with tests"]]`.
- **target-packs/README.md**: a row: `native` · Native Android (Kotlin, Jetpack Compose) and iOS (Swift, SwiftUI)
  apps; each screen written for both (`syntax: native`) · The mobile preview (the same tokens); native views do not
  run in a browser.
- **components/tools/build-tokens.js**: `Theme.kt` and `Theme.swift` carry the tokens by hand; the script can write
  them as it writes `tokens.ts` and `tokens.dart`.
- **CI** (`.github/workflows/build.yml`):

  ```yaml
  native-android:
    runs-on: ubuntu-latest
    defaults: {run: {working-directory: target-packs/native/starter/android}}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: {distribution: temurin, java-version: 17}
      - uses: gradle/actions/setup-gradle@v4
        with: {gradle-version: "8.14"}
      - run: gradle test
  native-ios:
    runs-on: macos-15
    defaults: {run: {working-directory: target-packs/native/starter}}
    steps:
      - uses: actions/checkout@v4
      - run: xcodebuild test -scheme ObdxApp -destination 'platform=iOS Simulator,name=iPhone 16'
  ```

  The starter has no Gradle wrapper (`gradlew` and its jar are binary; generate them once with `gradle wrapper` and
  commit them) and no Package.resolved yet.
- **Generated code check**: with `-Dscaffold.out=<folder>` the native scaffold test writes the Compose screen, the
  SwiftUI view and the texts; copy them into the starter and run both builds to check the generated code compiles.

## Checks run
